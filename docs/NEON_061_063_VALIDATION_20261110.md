## What is still open

**Neon main and Render reviewer staging are unchanged.** The existing free Render service runs the older deployment branch, auto-deploy off.
Its runtime filesystem is **ephemeral**: [Render's official storage documentation](https://render.com/docs/disks)
confirms persistent disks require paid services. A paid disk or free trial is
**not an acceptable workaround under the owner's constraints**. Secure,
verified persistent private storage or a matched recoverable backup is required
before promoting a reviewer build that must retain uploaded PDFs. The existing Neon main still has **059/060 only**.

Before main migration or deployment, verify a paired **hosted database + actual private PDF bytes** backup and restore into a separate destination, including file digests and authenticated download results. No connected Render private-file export capability was available in the inspected tools; Neon contains three ready-file *records*, not an accessible backup of their contents. An earlier local database/PDF restore is useful evidence, but is not a hosted restore.

After a verified paired restore, a controlled release may apply **only 061 → 062 → 063** to the intended main database and deploy the matching code, followed by authenticated reviewer role acceptance. Institutional production activation additionally requires the chosen identity provider, official identity mapping, real departmental policy approval, records accessibility/privacy, and a decision about historical Guide/evaluator assignments after reinstatement. See [release issue #4](https://github.com/10Stardust01/Smart-Pro/issues/4) and [assignment issue #9](https://github.com/10Stardust01/Smart-Pro/issues/9).

Do **not** interpret this rehearsal as live deployment, production acceptance, an approved paid service, or permission to rerun 059/060.
