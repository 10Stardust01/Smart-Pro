# Sprint 1 Django adapter scaffold

This is an initial, read-only HTTP adapter over the preserved synopsis service,
not a replacement for the validated FastAPI harness or a completed Sprint 1.
It includes unmanaged project/composite-key read mappings and a scoped case GET.
No migration, production login, team write endpoint or admin is enabled.

From a new Python 3.12 environment, install `pip install -r backend/requirements.txt`
from the repository root. Provision an isolated PostgreSQL 16 test database using
the root README. Export its restricted `DATABASE_URL`, `SMARTPRO_DB_ROLE=smartpro_runtime`
and a generated `DJANGO_SECRET_KEY`. Run `python backend/manage.py check`.
For the synthetic `api_seed.sql` fixtures only, also explicitly set
`SMARTPRO_ENV=demo` and `SMARTPRO_DEMO_AUTH=YES`; run
`python backend/manage.py runserver 127.0.0.1:8000 --noreload`.

GET `/api/v1/submission-cases/19000000-0000-4000-8000-000000000001`
with `X-Demo-User: student-a`. Use actual UUIDs. Demo aliases are not accepted.
With either demo switch absent, protected requests fail closed with 401.
The domain rechecks effective membership/account/project authority in PostgreSQL.
No header-based production authentication is provided.

Run `python backend/verify_compatibility.py` only after the original suite finishes;
the probe requires `ALLOW_SMARTPRO_TEST_DB=YES`, checks the database name, resets
that isolated test database to API fixtures, and compares catalog state before/after
Django introspection and read operations within each fixture phase, before any
reset. Column, function and trigger definitions supplement the original catalog.
Run `python -m unittest discover -s backend -p 'test_*.py'` for database URL
configuration checks. TLS options in DATABASE_URL are retained for Django.
The probe writes reproducible JSON evidence; CI artifacts describe the current head,
while committed evidence files remain historical snapshots.

Do not run `migrate`, schema synchronization or autogenerated CRUD against the
academic tables. `managed=False` prevents Django schema ownership; it does not
prevent model writes or authorize users. See `docs/SPRINT_1.md` for next work.
